## v1.1.1：动作 ↔ 子动作时间关联（相对时间模型）

- 用户选择三项：改父动作子动作跟随、子动作必须落在父窗口内、子动作起始相对父动作计算。
- **数据模型**：`ModuleData.offsetFromParentMs?`（子动作相对最近祖先动作起始的偏移，动作/汇总行不用）。`migrateProject` 的 `deriveSubActionOffsets` 为旧子动作按父绝对 start 反推偏移，并清除指向祖先的旧依赖（避免与相对模型冲突）。新建子动作 / `setTaskTiming` 写相对偏移。
- **调度器核心**（`computeSchedule` Pass 1.5 + 1.6，在依赖排程后、rollup 前）：Pass 1.5 按树序解析 `sub.start = 祖先动作resolvedStart + offset`（嵌套链式），改父动作或依赖级联时子树跟随；前置任务作为硬下限（max）。Pass 1.6 把含子节点的 action/subaction 时长扩到覆盖子树最终边界，排在依赖约束之后，修复「父动作 auto + 前置时被拉回、子戳出父窗口」旧 bug。
- **setTaskTiming 不再用 autoExpandParentTimes 写回**（它会用陈旧子树时间把编辑中的父 start 拉回）：改为 commit 前用 `computeSchedule` 预演，仅生成准确的「父已扩展」提示 changes。`autoExpandParentTimes` 函数保留（仅测试用）。
- **三格式**：Excel 动作表新增「相对父偏移 (ms)」列（col offsetFromParentMs，导入回写）；JSON/CSV 走快照自动带。`cycleEngine` 用 `...m` 展开自动保留该字段（同周期父子一起平移，偏移不变）。
- 编辑框：子动作「开始/结束」显示并输入相对偏移（label 改「开始偏移/结束偏移」+ 蓝色说明），动作仍绝对。5 语言补 `gantt.subRelativeHint/startOffset/endOffset`。
- 测试 134 项全过（新增依赖引擎 6 条 + store 4 条 + Excel 往返 1 条；旧 rollup 测试改用 offset 构造）。typecheck/vite build/build:web 通过。

## v1.1.2：统一新增子动作的时间坐标系

- 用户反馈：新增子动作对话框填「开始 1000」，打开任务编辑器却显示「开始偏移 0」，看似冗余冲突。根因是两个对话框用了不同坐标系——新增框用绝对时刻（默认父 start），编辑器用相对偏移。数据本身没错（父 start=1000 时二者等价），但 UI 误导。
- 修复：`AddNodeDialog` 子动作的开始字段改「开始偏移 (ms)」，默认 0（与父对齐）；节点类型下拉切换时重置该值；提交时子动作传 `offsetFromParentMs`、动作仍传 `startMs`。`addAction` options 新增可选 `offsetFromParentMs`，提供时直接用、不提供才从绝对 start 反算（兼容程序化调用）。
- `TaskEditorDialog`：子动作「结束偏移」是派生值（开始偏移+时长），改为只读（readOnly + 半透明 + title 提示），避免两个可编辑框互相覆盖；动作仍可编辑 endMs。effect 依赖含 durationMs/offsetFromParentMs，派生值自动刷新。5 语言补 `gantt.endOffsetReadonly`。

## v1.2.0：反转父子时间模型为 child-driven（子为源、父为汇总）

- 用户思考后决定：以子动作时间为准，动作时间 = 子树最早开始~最晚结束；一开始无子动作的动作可自由编辑时间，加子动作后自动变汇总、改子动作父自动更新。父依赖整棵子树平移。这是推翻 v1.1.1 相对偏移模型的重大反转。
- **模型**：所有 action/subaction 回到绝对时间；`offsetFromParentMs` 仅为 v1.1.x 迁移输入，读入即还原绝对 start 并清除。叶子（无子节点）可编辑、参与依赖排程；容器（有子节点）时间 = rollup、只读。
- **调度器**（`dependencyEngine.computeSchedule`）：Pass1 依赖排程所有节点；Pass2 rollup 时容器只取子树边界不取 own；Pass1.5 容器前置约束按 delta 整体平移子树所有可排程叶子（深→浅叠加，`descendantLeaves` 用 local seen 拷贝防环）；Pass1.7 平移后沿拓扑序把依赖被平移叶子的外部后继一并前推（修复跨容器依赖硬下限 bug）。`ScheduledTask.isLeaf` 现在只对可排程叶子为 true。
- **冲突防护**：新增 `wouldCreateHierarchyConflict/isAncestorOf`——节点与祖先/后代不能互为前置（层级-依赖环），兄弟及跨容器普通依赖合法。接入 `addPredecessor/updatePredecessor`、UI 前置候选过滤、migrate 清理。
- store：`setTaskTiming` 对容器写入直接忽略（避免第二真相源）；`addAction` 子动作走绝对 startMs；`materializeSubActionTimes` 替换 `deriveSubActionOffsets`。
- UI：AddNodeDialog 开始回绝对、默认父 endMs；TaskEditorDialog 容器时间三框只读+蓝色说明，叶子绝对可编辑。
- Excel「相对父偏移」列保留但导入不再读回；JSON/CSV 快照自动带绝对时间。
- 测试 149 项全过（重写父子关联/迁移/Excel 测试，新增层级冲突 8 条 + 跨容器传播 1 条 + 叶子到容器过渡 2 条）。typecheck/vite build/build:web 通过。
- 版本 1.1.2 → 1.2.0；产物 `release/DYNMECH-CycleView-Portable-1.2.0.exe`（80M）、`release/DYNMECH-CycleView-Setup-1.2.0.exe`（97M）。
