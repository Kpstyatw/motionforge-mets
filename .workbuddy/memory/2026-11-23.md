## 修正：PDF 空白首页的真正根因（11:35–11:41）

- 用户反馈"还是有空白"，确认用的是源码（非旧 exe）。上次（11:32）"标题预留 50→120px"的诊断**不解决大项目空白首页**，本次彻底实测纠正。
- 实测方法：环境全局 `ELECTRON_RUN_AS_NODE=1` 使 Electron 打印无法用；改用系统 Edge + 项目自带 `playwright-core`，按 Electron 完整参数（`pageSize:A3/landscape/preferCSSPageSize/displayHeaderFooter` + 页眉页脚模板）复刻打印；再用 Python 解析 PDF 内容流统计每页矩形/文本数判断空白页。
- **真正根因**：`pageHMm` 被 `Math.min(594, …)` 截断到 594mm，但大项目（60/80/120 行）时序 SVG 高达 2156–4196px，超过 594mm 页的可打印高度（约 2132px）。`page-break-inside:avoid` 把整节推到第 2 页，首页只剩页眉页脚（解析显示 p1 仅 3 个矩形=页眉页脚线）。小项目（3–50 行）页高远低于 594mm，不触发——所以之前合成数据没复现。多周期时参数表还会多溢出一页。
- **修法**：`pdfExport.ts` 去掉 pageHMm 的 594mm 上限，`pageHMm = max(120, (contentH + 120)/pxPerMm + headerMm + footerMm)`，让页面高度真正跟随最高的图表。实测 60/80/120 行场景均为稳定 3 页、首页矩形数 224/294/434（完整图表），空白首页消失。`exportVisibility.test.ts` 新增大项目用例断言页高 >594mm 且可打印高度始终大于 SVG 高度。
- 关键经验：**排查 PDF 分页必须用能真实复刻 Electron printToPDF 的方式**（Edge+playwright-core），纯结构/CSS 单测无法发现此类溢出分页。
- 验证：typecheck 通过，16 文件 / **182 项**测试通过，`vite build`、`build:web` 均通过。临时探针已清理。**release exe 仍未重新打包（09:49 版本）。**
