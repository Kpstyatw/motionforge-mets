## 依赖箭头向左折返穿柱问题（用户截图反馈）

- 现象：用户截图中依赖箭头出现向左方向布局、穿过绿色柱状条。
- 根因：`GanttView.tsx` 旧路由 `elbow = Math.max(x1 + 10, x2 - 14)`，当目标锚点紧贴或早于源锚点（`x2 - x1 < 24`，lag 0 / 负 lag / 容器 rollup）时，最后一段是从 `elbow > x2` 向左折回到 x2，横穿目标条；FF/SF 进入右端时同样有穿条风险。
- 修复：新建 `src/lib/dependencyArrow.ts` 纯函数 `routeDependencyArrow`。两种路由：
  - 普通 FS 且 `x2 - x1 >= 28`：紧凑四段折线，垂直腿落在两柱之间。
  - 其余（SS/FF/SF、紧邻、倒挂）：从源外侧出 → 走源行外侧 gutter（barH/2+8）→ 在目标进场侧外侧垂直进入 → 短水平段进入锚点；最后一段永远指向锚点，不穿条。
- `GanttView.tsx` 的 `linkPaths` 改用该函数，传 `leaveRight=startFromEnd`、`enterLeft=!endAtFinish`。
- 测试：新建 `dependencyArrow.test.ts` 5 项（前进紧凑、lag0 紧邻、倒挂、FF/SF 右端进入、目标在上方 gutter 方向）；`GanttView.test.ts` +1 项 SSR 断言渲染路径从左侧进场、6 点绕行。
- 验证：typecheck 通过，19 文件 / **204 项**测试通过，`vite build`、`build:web` 均通过。
- 注意：截图工具本轮未返回图像分析，修复依据代码定位 + 用纯路由函数复刻截图坐标验证（前进/倒挂两条路径均符合预期）。
- **release exe 未重新打包**（源码版本 1.2.1，exe 仍是 09-23 的旧版）。

## 导出的 PDF 箭头没变化（同日追加）

- 用户反馈界面改了但 PDF 导出不变。根因：PDF / 画布各自有**独立的箭头绘制代码**，不是复用界面 GanttView 的路径：
  - `src/lib/reportGanttSvg.ts:232` 旧 `elbow = max(fromX+8, toX-12)`（PDF）
  - `src/lib/canvasRenderer.ts:253` 旧 `elbowX = max(fromX+8, toX-12)`（画布/MP4 帧）
  - 箭头头部也写死 `toX-5/toX-6` 朝左，绕行后方向会错。
- 修复：`dependencyArrow.ts` 抽出共享的 `dependencyArrowPoints()`（返回点数组）+ `arrowHead(points)`（按最后一段方向生成箭头两翼）；`routeDependencyArrow()` 仍给界面 SVG path。PDF 与画布都改为逐段画点数组并用动态箭头头。
- **重要经验**：这个项目同一视觉元素有多份渲染实现（GanttView / reportGanttSvg / canvasRenderer），改可视元素必须全局 grep 同类算法，不能只改界面一处。
- 测试：新建 `reportGanttArrow.test.ts` 2 项（解析 PDF SVG 橙线：目标行不向左折返、gutter 在两行之间、箭头两翼朝左展开）。探测时发现 SVG 输出带 labelW≈205 偏移，断言改用线段相对关系而非绝对 x。
- 验证：typecheck 通过，20 文件 / **206 项**测试通过，`vite build`、`build:web` 均通过。exe 仍未重打包。
