## 核心概念：物理模块 vs 资源（用户 2026-11-19 明确）

- **模块 / 机构**（`ModuleData`，`kind='module'|'mechanism'`）= 仪器里真实存在的**物理模块 / 硬件部件**。属于流程树，用来描述设备结构与动作归属，是物理实体视角。
- **资源**（`Resource`）= 在**物理模块和流程基础上抽象**出来的可占用单元，服务于冲突检测与调度。它不等同于物理模块：可以对应一个机构（抓手），也可以是机构的一部分（清洗盘的孔位）或多个模块协同形成的抽象能力。资源不构成流程树。
- 两者是「物理实体 → 抽象资源」的**映射**关系，不是同一对象的两份重复数据，也不能简单一对一绑定。绑定通过机构节点的 `resourceId` 显式表达，映射基数由数据决定（可一对一、一对多、多对一）。
- 因此不要再使用「机构与资源是同一物理对象的两个身份」「隐式重复」这类措辞。资源树 + 相位模型（清洗盘→孔位、随盘旋转、每周期选孔）正是「抽象资源」区别于「物理机构」的体现。

## 资源 / 机构统一模型（设计已确认，实施中）

- 目标模型四条规则 + 旋转相位见 `SECONDARY_DEV_GUIDE.md` 第 5 章，是唯一依据。
- **归属 ≠ 占用（用户 2026-11-19 最终明确，推翻原“自动占用”决策）**：模块/机构绑定资源（`resourceId`）只表示**层级归属 / 泳道分组**，让流程图与资源图层级一致；它**绝不**让该节点下所有流程动作占用该资源。`deriveMechanismAllocations` 已删除，`useCycleView` 只用 `project.allocations`（在流程甘特图为动作声明的 `offsetMs+durationMs`）投影占用。资源甘特图只显示显式声明的占用窗口，并检测冲突。
- 资源新增入口：流程图编辑器（任务编辑器→资源占用→新建）与资源视图（资源管理对话框）均可；资源视图每行有铅笔按钮，点击打开资源管理器并定位高亮该资源，可改名称/归属/类型/旋转；归属下拉可随时更换。
- 冲突判定按槽位 id（身份）不按空间位置；旋转只改位置不改身份。
- 分阶段：阶段 1 做资源层级 + 归属 + 显式占用 + 冲突传播 + UI + 三格式往返；阶段 2 做物料状态推导。

## 动作 ↔ 子动作时间模型（用户 2026-11-20 明确，v1.1.1）

- **动作（action）= 绝对时间；子动作（subaction）= 相对时间**。子动作的起始用 `offsetFromParentMs`（相对最近祖先动作 resolved start 的偏移）表达；任务编辑器里子动作的「开始/结束」输入就是这个偏移，不是绝对时刻。
- 用户在三项中选了：改父动作子动作跟随平移 + 子动作必须落在父窗口内 + 子动作起始相对父动作计算。
- 权威实现在 `computeSchedule`：Pass 1.5 依赖排程后按树序传播子动作 start（父 start + offset，嵌套链式，前置任务仍作硬下限），Pass 1.6 把含子节点的动作时长扩到覆盖子树边界（排在依赖之后，修复 auto+前置时父被拉回的 bug）。`autoExpandParentTimes` 已不在 store 写入路径使用（仅留测试），不要再恢复它写回，否则会把编辑中的父 start 拉回。
- 旧的「子动作 FS 依赖父动作」在迁移时清除；旧绝对子动作按父 start 反推 offset。Excel 有「相对父偏移 (ms)」列。
